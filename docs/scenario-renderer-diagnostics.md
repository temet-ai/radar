# Fast scenario renderer diagnostics

Use deterministic checks to locate a failure before inspecting images. The
existing GitHub checkpoint is generated by a real hosted scenario, rendered by
Ratatui, and replayed through the actual headless Ink App. This tool diagnoses
that one checkpoint; it does not replace all renderer or protocol tests.

```sh
# Cheap: no Cargo, Node, npm or renderer processes.
scripts/check-scenario-renderers --preflight-only

# Full: fixed real producer, then the existing headless Ink test.
scripts/check-scenario-renderers

# Optional new directory outside the checkout, under an existing owned parent.
scripts/check-scenario-renderers --output /tmp/radar-renderer-investigation

# Diagnostic regression tests only; Python standard library, no Rust/Ink build.
python3 scripts/scenario-renderer-diagnostics-tests.py
```

The output directory must be new and outside the repository; an existing path or
symlink path is refused. Default output is a fresh private temporary directory.
The tool never updates committed fixtures or accepts snapshots. It clears
`RADAR_SCENARIO_FIXTURES_DIR`, ignores an ambient capture path, and disables Insta
updates for its subprocesses. Keep artifacts only as long as needed; they contain
synthetic fixture/rendered content and bounded command-log tails, not live
provider or desktop captures.

## Read the stage before reading a screenshot

| Stage | What it establishes | Useful next action |
| --- | --- | --- |
| `preflight` | Both inputs exist, decode, and match this recipe's basic shape, dimensions and semantic marker | Fix missing/malformed input or inspect the intended fixture source; do not start a renderer to diagnose JSON syntax |
| `dependencies` | Required commands and the locked Ink test executable are available | Restore the normal project toolchain/dependencies separately; the diagnostic does not install them |
| `producer-freshness` | `scripts/scenarios github-denied-detail` actually passed, including its comparison of committed JSON/text with the fresh scenario | Inspect the producer log and its stale fixture/assertion error before running Ink |
| `ink` | The actual Ink checkpoint test ran and supplied its captured frame | Inspect test errors or timeout; absent capture is incomplete, never matching empty output |
| `text-parity` | Captured Ink and Ratatui outputs agree under the existing normalization | Use the first differing row and bounded context to narrow content/layout regressions |

Later stages stay `not-run` when prerequisites fail. A preflight-only success is
explicitly **not qualified**: no freshness, protocol completeness, Ink replay or
visual correctness has been established. The full command preserves nonzero
subprocess failures and reports timeouts as failures. A failed Ink assertion
remains failed even if its final captured text happens to match.

`--timeout-seconds` controls a bounded per-command diagnostic wait (default 300,
range 1–3600), not repository test budgets. The POSIX runner drains output with a
bounded retained tail and kills/reaps its own process group on timeout/interruption.
Do not increase a timeout to conceal a regression. Use the normal single compile
lane and resource limits when the producer must compile.

## Small artifacts, precise evidence

`report.json` records named stage status, fixture content hashes, producer source
hash, dimensions, evidence
scope, commands and a minimal rerun command. Fixture hashes must remain unchanged
across producer and Ink execution; a mid-run mutation fails instead of attributing
results to the wrong input. On replay, artifacts include
`expected.normalized.txt`, `actual.ansi.txt`, `actual.normalized.txt` and bounded
per-command logs when available. The report includes the first mismatch with at
most five rows and 120 Unicode codepoints per side per row. Read this context
before loading full frames into a model; retained text files allow deeper local
inspection when the short context is insufficient.

Coordinates are one-based Unicode **codepoints**, not grapheme clusters, terminal
display cells or pixels. CJK and combining sequences can occupy different numbers
of those units. The tool keeps raw ANSI output, strips the same CSI sequences as
the existing Ink test, trims its trailing whitespace and final blank rows, and
does not Unicode-normalize authored content. Equal normalized text does not prove
colour, styling, display-cell geometry, trailing-space fidelity, font rendering,
pixels or real terminal/IPC behavior.

Use the existing cell/protocol tests for their specific contracts. For a genuine
style or image question, first narrow the affected component/state and then use
`scripts/shots` (sample-data SVG/PNG) or the offline `radar-ink-live` workflow where
supported. Confirm which renderer actually produced the evidence and inspect the
actual image at the relevant dimensions. Never infer pixel fidelity from text or
from an uninspected image, and never bypass an access restriction to obtain one.

## Deliberate golden changes

A stale producer comparison can mean a regression or an intentional change. The
diagnostic cannot decide which. Review the intended behavior, regenerate only
through the documented producer path when explicitly appropriate, inspect the
JSON/text and renderer output, then rerun this check with regeneration disabled.
Missing files, an empty capture or changed expectations are not an excuse to skip
coverage. Keep fixture-update approval distinct from diagnosis.
